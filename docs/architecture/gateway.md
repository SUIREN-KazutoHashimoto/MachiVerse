# ゲートウェイ設計

## 1. 目的

ゲートウェイは、シミュレーションコアと一般ビュー・管理ビューの間に位置する接続境界です。

MachiVerse では、1つのシミュレーションコアに対して複数のゲートウェイを配置します。ゲートウェイはシミュレーション状態を参照用にキャッシュし、一般ビューや管理ビューからの高頻度な読み取り要求を吸収することで、シミュレーションコアを計算処理へ専念させます。

## 2. 主な責務

- 一般ビュー・管理ビューからの要求受付
- 一般向け参照要求と管理要求の論理的分離
- シミュレーション状態の参照用キャッシュ
- キャッシュからの高頻度な読み取り応答
- シミュレーションコアへの管理要求仲介
- シミュレーションコアからの外部公開状態取得
- 外部クライアント接続の管理
- 認証・認可を配置する境界の提供
- 負荷分散・水平スケール
- 通信上のエラー処理
- 外部公開モデルへの変換
- 必要に応じた流量制御

## 3. 責務外

- シミュレーションルールそのものの決定
- エージェントの内部状態遷移ロジック
- シミュレーション時間の進行
- シミュレーション状態の正本管理
- 一般ビュー・管理ビューの描画
- 管理要求の最終的なシミュレーション整合性判断

## 4. コアとの多重度

シミュレーションコアとゲートウェイは 1 対多の関係です。

```text
                 ┌─ ゲートウェイ A
シミュレーション ├─ ゲートウェイ B
コア             ├─ ゲートウェイ C
                 └─ ...
```

ゲートウェイは複数インスタンスへ水平スケール可能であることを前提とします。各ゲートウェイは外部要求を処理しますが、シミュレーション状態の正本は保持しません。

## 5. キャッシュ

### 5.1 目的

キャッシュの第一目的は、外部からの参照要求をコアから切り離すことです。

一般ビューや管理ビューから同一または類似状態への参照が集中しても、要求数に比例してコアへ問い合わせが発生しない構成を目指します。

### 5.2 基本原則

- キャッシュは参照専用の複製であり正本ではない。
- 正本は常にシミュレーションコアにある。
- 一般ビューへの応答は原則としてキャッシュから行う。
- 管理ビューの参照も、正本への即時照会が不要な情報はキャッシュを利用する。
- キャッシュ内容を直接編集してシミュレーション状態を変更してはならない。
- キャッシュの遅延・失効・更新失敗を前提に設計する。

### 5.3 キャッシュ更新

コアからゲートウェイへの状態同期方式は未確定です。候補となる方式には Push、Pull、差分、スナップショット等がありますが、現時点では採用方式を固定しません。

複数ゲートウェイ間で、どの程度同一時点の状態を保証するかも今後定義します。

## 6. 要求種別

### 6.1 一般ビューからの要求

一般ビューはリードオンリーです。

ゲートウェイは一般ビューからシミュレーション状態変更要求を受け付けません。一般ビュー向け境界では、公開済み状態の参照のみを提供します。

### 6.2 管理ビューからの参照要求

管理ビューは監視・診断・運用確認のために状態を参照できます。通常の状態参照はキャッシュを利用できる構成とします。

### 6.3 管理ビューからの管理要求

管理ビューはゲートウェイを経由してコアへ管理操作を要求できます。

ゲートウェイは以下を担当します。

- 管理者としての認証・認可境界
- 要求形式の検証
- 管理要求と一般参照要求の識別
- コアへの安全な仲介
- 通信上の再試行やエラー処理を配置する境界

シミュレーション上、その操作を実行してよいかという最終判断はコア側が持ちます。

## 7. 外部公開モデル

コア内部のデータ構造をそのままビューへ公開しません。ゲートウェイは外部公開用モデルへ変換し、コアの内部実装変更を外部契約から隔離します。

## 8. スケールアウト

ゲートウェイは複数インスタンスで稼働できる構成を前提とします。

設計時には以下を検討対象とします。

- キャッシュを各インスタンスが個別に持つか共有するか
- キャッシュ更新情報を各インスタンスへどう配布するか
- インスタンス間の状態差をどこまで許容するか
- セッション状態をどこに持つか
- 接続先インスタンスが変わっても継続可能か
- 一部インスタンス障害時に他インスタンスへ切り替えられるか
- ゲートウェイ増設時にコア負荷が線形増加しないか

## 9. 流量制御

外部要求量が急増してもシミュレーションコアの計算処理を守れるよう、ゲートウェイを流量制御境界とします。

一般ビューからの参照トラフィックはキャッシュで吸収します。管理要求については、必要に応じてレート制限、キューイング、バックプレッシャー等を検討します。

## 10. データ所有権

ゲートウェイが保持するシミュレーション情報は参照用キャッシュです。

シミュレーション状態の正本はシミュレーションコアが所有します。ゲートウェイが独自判断でシミュレーション状態を確定・変更することはありません。

## 11. 他領域との関係

### シミュレーションコア

- 1つのコアに複数ゲートウェイが接続する。
- 外部公開可能な状態を取得してキャッシュする。
- 管理ビューからの管理要求を仲介する。
- コア内部の可変データ構造を直接操作しない。

### 一般ビュー

- 一般ビューはゲートウェイにのみアクセスする。
- 一般ビューへは読み取り専用境界を提供する。
- 状態変更要求は受け付けない。

### 管理ビュー

- 管理ビューはゲートウェイにのみアクセスする。
- 参照情報を返す。
- コアへ影響する管理操作を認証・認可した上で仲介する。

## 12. 禁止する依存・実装

- 一般ビューからの状態変更要求をコアへ伝達すること
- キャッシュをシミュレーション状態の正本として扱うこと
- キャッシュを書き換えることでコア状態を変更しようとすること
- シミュレーションルールをゲートウェイ内へ複製すること
- コア内部の可変状態を直接書き換えること
- 単一ゲートウェイだけを前提とした構成に固定すること

## 13. 今後決定が必要な事項

- コアからゲートウェイへの状態配信方式
- Push / Pull の採否
- 全量・差分・スナップショットの使い分け
- キャッシュ更新頻度
- キャッシュ失効条件
- 複数ゲートウェイ間の整合性レベル
- キャッシュ保存場所
- 通信プロトコル
- API 形式
- 認証方式
- 認可モデル
- セッション管理方式
- 負荷分散方式
- 流量制御方式
- 再試行方針
- 冪等性要件
- API バージョニング
- 可観測性方式
