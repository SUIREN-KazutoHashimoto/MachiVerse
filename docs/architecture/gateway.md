# ゲートウェイ設計

## 1. 目的

ゲートウェイは、シミュレーションコアと一般ビュー・管理ビューの間に位置する接続・認可・緩衝・調停境界です。

1つのシミュレーションコアに対して複数のゲートウェイを配置でき、外部利用者数や参照要求数の増加をコアへ直接集中させません。ゲートウェイは参照用キャッシュと約1秒分の遅延バッファを持ち、コアを30Hzのシミュレーション計算へ専念させます。

一般ビュー由来のシミュレーション干渉要求は、各ゲートウェイ内で認証・認可・集約・競合整理を行います。複数ゲートウェイ構成では、コアがランダムに選出した1台のマスターゲートウェイへ各ゲートウェイの操作バッチを集約し、マスターゲートウェイがゲートウェイ間の競合を整理したうえで、コアへ一括リクエストします。

複数シミュレーションコア構成では、各コアに少なくとも1つのゲートウェイを用意します。利用者が現在接続中のゲートウェイの担当範囲外にある情報を必要とする場合、現在側のマスターゲートウェイが別コア側のゲートウェイへのProxyとして情報を取得します。利用者が必要とするデータの範囲やゲートウェイ負荷の変化により、別ゲートウェイへ接続を移す方が適切になった場合は、マスターゲートウェイがハンドオーバーを扱います。

## 2. 主な責務

- 一般ビュー・管理ビューからの要求受付
- 一般ビュー利用者の認証・ロール認可
- ロールに応じた参照情報の制御
- 一般ビュー由来操作のローカル集約
- 同一ゲートウェイ内の競合検出・競合調停
- ローカル操作バッチの形成
- 非マスター時のマスターゲートウェイへの操作バッチ転送
- マスター時の全ゲートウェイ操作バッチの集約
- マスター時のゲートウェイ間競合検出・競合調停
- マスター時のコア向け最終操作バッチ形成・一括送信
- マスター選出・変更通知の受理
- 複数コア構成における担当範囲外データのProxy取得
- 複数コア構成における利用者接続先ゲートウェイのハンドオーバー調整
- 管理ビューからの運用・設定・コマンド要求の仲介
- シミュレーション状態の参照用キャッシュ
- 約1秒分の遅延バッファ管理
- 外部クライアント接続管理
- 負荷分散・水平スケール
- 通信エラー処理・流量制御
- ゲートウェイ・一般ビュー間プロトコルの所有
- ゲートウェイ・管理ビュー間プロトコルの所有
- ゲートウェイ間プロトコルの所有

## 3. 責務外

- シミュレーションルールそのものの決定
- エージェント内部状態遷移ロジック
- シミュレーション時間の進行
- シミュレーション状態の正本管理
- シミュレーション上の最終的な操作妥当性判断
- マスターゲートウェイの選出決定
- シミュレーションコア・ゲートウェイ間プロトコルの所有

## 4. 基本構成とマスターゲートウェイ

シミュレーションコアとゲートウェイは1対多です。複数ゲートウェイが存在する場合、コアが接続中のゲートウェイから1台をランダムにマスターゲートウェイとして選出します。

```text
                    ┌─ Gateway A ─┐
一般ビュー群 ──────>│ local batch │
                    └──────┬──────┘
                           │
                    ┌──────▼──────┐
一般ビュー群 ──────>│ Gateway B    │  ← Master
                    │ local + global│
                    │ arbitration   │
                    └──────┬──────┘
                           │ final batch
                    ┌──────▼──────┐
                    │ Simulation  │
                    │ Core        │
                    └─────────────┘
                           ▲
                    ┌──────┴──────┐
一般ビュー群 ──────>│ Gateway C    │
                    │ local batch  │
                    └─────────────┘
```

マスターは恒久的な固定ノードではなく、コアが選出する役割です。

## 5. マスター選出責任

マスターゲートウェイの選出責任はシミュレーションコアが持ちます。

- 選出対象は、その時点でコアが有効な接続先として認識しているゲートウェイとする。
- 選出方式はランダムとする。
- 選出結果を対象ゲートウェイ群へ通知する。
- マスターが利用不能になった場合はコアが再選出する。
- 再選出の検知条件、タイムアウト、再選出までの猶予時間等の数値は今後定義し、調整可能なものは外部Config化する。

ランダム選出に利用する具体的な乱数方式、重み付けの有無、直前マスターの再選出可否は未確定です。

## 6. プロトコル責任

| 境界 | 所有者 | 設計書 |
|---|---|---|
| コア ↔ ゲートウェイ | シミュレーションコア | `docs/protocols/core-gateway.md` |
| ゲートウェイ ↔ 一般ビュー | ゲートウェイ | `docs/protocols/gateway-view.md` |
| ゲートウェイ ↔ 管理ビュー | ゲートウェイ | `docs/protocols/gateway-admin-view.md` |
| ゲートウェイ ↔ ゲートウェイ | ゲートウェイ | `docs/protocols/gateway-gateway.md` |

ゲートウェイ同士はコード・DLL・内部型を共有せず、ゲートウェイ間プロトコルだけを契約として通信します。

複数コア構成における、別コア側ゲートウェイへのProxy参照および利用者ハンドオーバーも、ゲートウェイ間の直接的なコード依存ではなくプロトコル契約に基づいて行います。具体的なメッセージ形式は別途プロトコル設計で定義します。

## 7. キャッシュと遅延バッファ

キャッシュは外部参照要求をコアから切り離すための参照用複製です。正本は常にコアにあります。

ゲートウェイはコアから受信した状態を基準値として約1秒遅延させ、30Hzで動作するコアの一時的な計算間隔・通信到着間隔の揺らぎを吸収します。この値は外部Configから変更可能です。

マスターゲートウェイであるかどうかに関係なく、各ゲートウェイは自身の参照要求処理と状態配信責任を持ちます。マスター役割は主としてコアへ向かう操作要求経路の集約点ですが、複数コア構成では担当範囲外参照のProxyおよび利用者ハンドオーバーの調整点としても機能します。

## 8. 一般ビュー利用者ロール

| ロール | シミュレーションへの干渉 | 参照範囲 |
|---|---|---|
| ダイバー | シミュレーション住民と同程度 | 参加者として許可された情報 |
| スペクテイター | 不可 | システムのバイタルに関係しない程度のステータス |
| モデレーター | シミュレーションおよび下位利用者へ限定的に可能。クリティカル操作は禁止 | スペクテイターと同等 |
| アドミニストレーター | シミュレーションへ完全に干渉可能 | 一般ビュー向け全ステータス |

一般ビューのアドミニストレーターは管理ビューの運用者権限とは別概念です。

## 9. 一般ビュー操作の処理

### 9.1 各ゲートウェイでのローカル処理

1. 一般ビューから操作要求を受信する。
2. 認証、ロール、対象、操作種別を検証する。
3. 権限外要求を拒否する。
4. 権限内要求をローカル集約対象へ追加する。
5. 同一ゲートウェイ内で競合を検出・調停する。
6. 競合整理済みのローカル操作バッチを形成する。

### 9.2 非マスターゲートウェイ

非マスターゲートウェイはローカル操作バッチをコアへ直接送信せず、現在のマスターゲートウェイへ送信します。

### 9.3 マスターゲートウェイ

マスターゲートウェイは、自身のローカル操作バッチと他ゲートウェイから受信したローカル操作バッチをまとめます。

その後、ゲートウェイ間で競合する外部要求を検出・調停し、コア向けの最終操作バッチを形成してコアへ一括送信します。

### 9.4 コア

コアはマスターゲートウェイから受信した最終操作バッチについて、現在の世界状態とシミュレーションルールに基づく最終妥当性判定を行い、正本状態へ反映します。

## 10. 競合調停の責務階層

競合調停は3段階に分けます。

1. **ローカル競合調停**: 各ゲートウェイが、自身に到達した要求同士を整理する。
2. **ゲートウェイ間競合調停**: マスターゲートウェイが、各ゲートウェイの操作バッチ間の外部要求レベルの競合を整理する。
3. **シミュレーション妥当性判定**: コアが、世界状態・シミュレーションルール上の最終実行可否を判断する。

ゲートウェイはシミュレーションルールそのものを複製しません。

## 11. マスター障害・切替

マスターゲートウェイが停止・切断・応答不能になった場合、コアが新しいマスターをランダムに再選出します。

切替時には、以下の重複・欠落防止が必要です。

- 旧マスターへ送信済みだがコアへ未送信のバッチ
- 旧マスターがコアへ送信済みだが結果未確定のバッチ
- 新マスターへの再送
- 同一操作の二重適用
- マスター世代の取り違え

そのため、マスター選出世代を識別できる情報、バッチ識別子、操作識別子、再送・冪等性の契約が必要です。具体的なフィールドはプロトコル設計で定義します。

## 12. スケールアウト

マスターゲートウェイは書き込み経路の集約点になるため、全ゲートウェイ台数・操作量の増加に対してボトルネックになり得ます。

現時点では1コア内のゲートウェイ群についてマスター1台方式を採用します。将来、実測上のボトルネックが確認された場合の分割方式は別途設計します。

参照トラフィックは各ゲートウェイのキャッシュで分散処理します。同一コア担当範囲内の通常参照をマスターへ集中させることはしません。ただし、別コア担当範囲へのProxy参照は現在側のマスターゲートウェイが仲介します。

## 13. 複数コア構成におけるProxy参照とGatewayハンドオーバー

### 13.1 基本方針

各シミュレーションコアには少なくとも1つのゲートウェイを用意します。利用者はシミュレーションコアそのものへ接続するのではなく、現在の利用状況に適したゲートウェイを通じて世界を参照・操作します。

利用者から見た世界の連続性を保つため、担当コアやゲートウェイの境界を越えた情報参照と、接続先ゲートウェイそのものの移動を分離します。

### 13.2 担当範囲外情報のProxy取得

現在接続中のゲートウェイの担当範囲外にあるデータが必要になっても、それだけを理由として即座に接続先を変更しません。

現在側のマスターゲートウェイが、対象データを保持する別コア側のゲートウェイへProxyとして要求し、取得した情報を現在の利用者へ返します。

これにより、担当範囲の境界付近を参照するたびにゲートウェイ接続が頻繁に切り替わることを避けます。

### 13.3 ハンドオーバー判断

接続先ゲートウェイのハンドオーバー判断には、少なくとも以下の2要素を使用します。

1. **ゲートウェイの負荷状況**
   - 現在接続中のゲートウェイおよび移動候補ゲートウェイの負荷を判断材料とする。
   - 具体的にどの負荷指標を使用するかは未確定とする。

2. **利用者が必要とするデータの取得範囲割合**
   - 現在ゲートウェイが自身の担当範囲・キャッシュから提供できるデータと、別ゲートウェイへのProxyによって取得するデータの割合を判断材料とする。
   - 少なくとも、Proxyで取得する側のデータ割合が現在ゲートウェイから直接取得する側を上回る場合は、別ゲートウェイへのハンドオーバーを行う条件とする。

したがって、利用者の位置が形式上の境界を越えたことだけではなく、実際にその利用者が必要としているデータ範囲と負荷状況を基準として接続先を決定します。

### 13.4 ハンドオーバー

ハンドオーバーが必要になった場合、現在側のマスターゲートウェイが移行を調整し、利用者をより適切な別ゲートウェイへ移します。

利用者体験上は「別コアへ接続し直す」ことを意識させるのではなく、一つの連続した世界を移動・参照している間に、インフラ上の接続先ゲートウェイが切り替わる構成を志向します。

移行中のセッション状態、未完了操作、認証・認可状態、重複接続、切断タイミング、操作結果の返却先等の具体的な引き継ぎ方法は未確定です。

### 13.5 スラッシング防止

境界付近や取得範囲割合が拮抗する状況で、短時間に接続先が往復し続けることは避ける必要があります。

ただし、ヒステリシス、最低滞在時間、評価期間等の具体方式は現時点では確定しません。これらに調整可能な数値を用いる場合は外部Configから変更可能にします。

## 14. 管理ビュー要求

管理ビューは一般ビューの最上位ロールではなく、コンポーネント運用のための別境界です。ログ、稼働・診断状態、外部Config、運用コマンド、シミュレーションへの運用上の干渉を扱います。

管理ビュー由来のコア干渉要求をマスターゲートウェイ経由へ統一するか、別の運用経路を持つかは今後定義します。

## 15. 禁止事項

- 非マスターゲートウェイが一般ビュー由来操作バッチを直接コアへ送信すること
- 複数ゲートウェイが同時にマスターとしてコアへ書き込み要求を送ること
- ゲートウェイ側でシミュレーションルールを複製すること
- マスター選出をゲートウェイ同士の暗黙合意だけで決定すること
- マスター切替時に識別情報なしで操作を再送すること
- キャッシュをシミュレーション状態の正本として扱うこと
- 一般ビューのアドミニストレーターへ管理ビュー専用権限を自動付与すること
- 担当範囲外のデータ参照が発生しただけで、負荷状況やデータ取得範囲割合を考慮せず常に即時ハンドオーバーすること
