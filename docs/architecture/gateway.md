# ゲートウェイ設計

## 1. 目的

ゲートウェイは、シミュレーションコアと一般ビュー・管理ビューの間に位置する接続境界です。

1つのシミュレーションコアに対して複数のゲートウェイを配置でき、外部利用者数や参照要求数の増加をコアへ直接集中させません。ゲートウェイは参照用キャッシュと約1秒分の遅延バッファを持ち、コアを30Hzのシミュレーション計算へ専念させます。

ゲートウェイは他コンポーネントとコード依存を持たず、独立したビルド・配布・実行単位として扱います。

## 2. 主な責務

- 一般ビュー・管理ビューからの要求受付
- 一般ビュー利用者の認証・ロール認可
- ロールに応じた参照情報の制御
- 一般ビューからの権限付きシミュレーション操作の仲介
- 管理ビューからの運用・設定・コマンド要求の仲介
- シミュレーション状態の参照用キャッシュ
- 約1秒分の遅延バッファ管理
- コアの計算間隔・状態到着間隔の一時的な揺らぎ吸収
- シミュレーションコアからの外部公開状態取得
- 外部クライアント接続の管理
- 負荷分散・水平スケール
- 通信上のエラー処理
- 外部公開モデルへの変換
- 必要に応じた流量制御
- ゲートウェイ・一般ビュー間プロトコルの所有
- ゲートウェイ・管理ビュー間プロトコルの所有

## 3. 責務外

- シミュレーションルールそのものの決定
- エージェントの内部状態遷移ロジック
- シミュレーション時間の進行
- シミュレーション状態の正本管理
- 一般ビュー・管理ビューの描画
- シミュレーション上の最終的な操作妥当性判断
- シミュレーションコア・ゲートウェイ間プロトコルの所有

## 4. コアとの多重度

シミュレーションコアとゲートウェイは 1 対多の関係です。

```text
                 ┌─ ゲートウェイ A
シミュレーション ├─ ゲートウェイ B
コア             ├─ ゲートウェイ C
                 └─ ...
```

各ゲートウェイは外部要求を処理しますが、シミュレーション状態の正本は保持しません。

## 5. コード・実行単位の分離

ゲートウェイは、シミュレーションコア、一般ビュー、管理ビューのいずれともコード共有を行いません。

- 他コンポーネントへのプロジェクト参照を持たない。
- 他コンポーネント DLL を参照しない。
- 共通 DTO ライブラリを通信契約として共有しない。
- 他コンポーネント内部型を参照しない。
- コンポーネント間の直接メソッド呼び出しを行わない。

## 6. プロトコル責任

### 6.1 シミュレーションコアとの境界

コア・ゲートウェイ間プロトコルの所有者はシミュレーションコアです。ゲートウェイは `docs/protocols/core-gateway.md` を契約として実装します。

### 6.2 一般ビューとの境界

ゲートウェイ・一般ビュー間プロトコルの所有者はゲートウェイです。`docs/protocols/gateway-view.md` に基づき、利用者ロールに応じた参照・操作境界を提供します。

### 6.3 管理ビューとの境界

ゲートウェイ・管理ビュー間プロトコルの所有者はゲートウェイです。管理ビューにはコンポーネント運用向けのログ・ステータス・設定・コマンド等の境界を提供します。

## 7. キャッシュと遅延バッファ

### 7.1 キャッシュ

キャッシュは外部からの参照要求をコアから切り離すための参照用複製です。正本は常にシミュレーションコアにあります。

一般ビューへの通常参照は原則としてキャッシュから応答し、キャッシュを書き換えることでシミュレーション状態を変更してはなりません。

### 7.2 約1秒の遅延バッファ

ゲートウェイはコアから受信した状態を外部へ即時公開せず、基準値として約1秒分の遅延を持たせます。この値は外部Configから変更可能とします。

目的は、30Hzで動作するコアの一時的な計算間隔・通信到着間隔の揺らぎを吸収し、外部へ安定した時間系列を提供することです。

具体的なバッファ実装、欠落・順序逆転・重複・1秒を超える遅延への対応は今後定義します。

## 8. 一般ビュー利用者ロール

一般ビューでは以下の4ロールを扱います。

| ロール | シミュレーションへの干渉 | 参照範囲 |
|---|---|---|
| ダイバー | シミュレーション住民と同程度 | 参加者として許可された情報 |
| スペクテイター | 不可 | システムのバイタルに関係しない程度のステータス |
| モデレーター | シミュレーションおよび下位利用者へ限定的に可能。クリティカル操作は禁止 | スペクテイターと同等 |
| アドミニストレーター | シミュレーションへ完全に干渉可能 | 一般ビュー向け全ステータス |

一般ビューのアドミニストレーターは、管理ビューの運用者権限とは別概念です。

## 9. 一般ビュー要求の処理

### 9.1 参照要求

1. 一般ビューが参照要求を送信する。
2. ゲートウェイが利用者を認証する。
3. 利用者ロールを確認する。
4. 要求対象がそのロールへ公開可能か認可する。
5. 原則としてキャッシュからデータを取得する。
6. 許可された情報のみを返す。

### 9.2 シミュレーション操作要求

1. 一般ビューが操作要求を送信する。
2. ゲートウェイが認証、ロール、対象、操作種別を検証する。
3. 権限外の要求はコアへ送信せず拒否する。
4. 権限内の要求のみコア・ゲートウェイ間プロトコルへ変換して中継する。
5. シミュレーションコアがシミュレーション上の最終的な妥当性を判断する。
6. 結果を一般ビューへ返す。

## 10. 管理ビュー要求の処理

管理ビューは一般ビューの最上位ロールではなく、コンポーネント運用のための別境界です。

管理ビューが扱う対象には以下を含みます。

- 各コンポーネントのログ
- 各コンポーネントの稼働・診断ステータス
- 各コンポーネントの外部Config確認・変更
- 運用コマンド
- シミュレーションへの運用上の干渉

具体的なコマンド一覧、各コンポーネントへの到達経路、Config反映方式は今後定義します。

## 11. 認可原則

- UI上の表示制御だけで認可を完結させない。
- 一般ビューからの参照・操作要求は要求単位でゲートウェイが認可する。
- スペクテイターからのシミュレーション干渉要求は拒否する。
- モデレーターによるクリティカル操作は拒否する。
- 下位利用者への操作ではロール上下関係も検証する。
- コアへ到達した操作の最終的なシミュレーション妥当性はコアが判断する。
- 一般ビューのアドミニストレーター権限を管理ビュー運用権限へ自動的に拡張しない。

## 12. スケールアウト

複数ゲートウェイで稼働する際は、以下を今後詳細化します。

- キャッシュを個別保持するか共有するか
- 遅延バッファを個別保持するか共有するか
- 利用者セッション・ロール情報をどこに保持するか
- 接続先ゲートウェイが変わった場合のセッション継続
- インスタンス間の公開時刻差
- 障害時の切り替え
- ゲートウェイ増設時にコア負荷が線形増加しない構造

## 13. 流量制御

参照トラフィックはキャッシュで吸収します。シミュレーション操作・管理要求については、必要に応じてロール別レート制限、キューイング、バックプレッシャー等を検討します。

調整可能な数値はゲートウェイの外部Configから変更可能にします。

## 14. 禁止事項

- 認可されていない一般ビュー操作をコアへ伝達すること
- スペクテイター由来の状態変更要求をコアへ伝達すること
- モデレーターのクリティカル操作をコアへ伝達すること
- 一般ビューのアドミニストレーターへ管理ビュー専用権限を自動付与すること
- キャッシュをシミュレーション状態の正本として扱うこと
- キャッシュ変更をシミュレーション状態変更として扱うこと
- シミュレーションルールをゲートウェイへ複製すること
- コア内部状態を直接操作すること
- 単一ゲートウェイだけを前提とすること
- プロトコル設計書に存在しない暗黙仕様へ依存すること

## 15. 今後決定が必要な事項

- 各利用者ロールの具体的な権限一覧
- 「システムのバイタルに関係しないステータス」の定義
- 「クリティカルな干渉」の定義
- ロール付与・変更・剥奪方式
- ダイバーと住民エージェントの対応方法
- 認証方式
- セッション管理方式
- ロール別流量制御
- コアからゲートウェイへの状態配信方式
- 複数ゲートウェイ間の整合性
- 実際の通信技術・シリアライズ形式
- 管理ビューから各コンポーネントへの運用コマンド経路
- ログ取得方式
- Config変更方式
- プロトコルバージョニング
