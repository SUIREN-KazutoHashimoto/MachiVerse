# 監視・ログ・決定論診断設計

## 確定方針

第250〜254問について、Q250=C、Q251=C、Q252=B（C相当の高度な決定論診断は将来アドオン）、Q253=C、Q254=Cを採用する。

### 構造化ログ

- 各コンポーネントは構造化ログを基本とする。
- ログには必要に応じて、コンポーネント名、インスタンス識別子、World Time、Operation ID、Batch ID、Master世代など、分散処理の追跡に必要な文脈を付与可能にする。
- 具体的なログ形式、シリアライズ方式、収集基盤、出力先は現時点では固定しない。

### 監視対象

- CPU、メモリ、接続数など一般的な稼働指標に加え、処理時間、キュー、エラー率、再接続、同期状態などを監視対象とする。
- MachiVerse固有の状態として、少なくとも次を観測可能にする。
  - Simulation CoreのWorld Time進行遅延
  - 標準30Hz目標との差
  - Gatewayの公開遅延バッファ状態
  - Gateway再同期状態
  - Master Gateway状態および世代
  - Operation再送状況
  - 重複排除に関する状態または診断情報
- 具体的なメトリクス名、収集間隔、アラート閾値は現時点では固定せず、調整可能な数値は外部Configで管理する。

### 決定論異常の検出

- 標準機能では、定期的または検証時にWorld State等の整合性ハッシュを比較できる仕組みを設ける。
- 同一条件の再実行やリプレイでハッシュが一致しない場合、決定論上の異常を検出可能にする。
- 標準機能では、詳細な不一致箇所の自動絞り込み、Operation履歴・Config・World Timeとの高度な相関解析までは必須としない。
- これらの高度な決定論診断は将来アドオンでC相当まで拡張可能とする。
- アドオンであっても標準世界の状態や決定論を破壊してはならない。

### ログ保持

- ログ保持期間、容量、ローテーション等はコンポーネントごとに外部Configで設定可能とする。
- ログ種別ごとに保持方針を分けられることを標準要件とする。
- 監査ログと大量の診断ログを同一の保持条件に固定しない。
- 保存媒体、圧縮方式、転送先などは現時点では固定しない。

### Admin Viewでの監視

- Admin Viewから各コンポーネントの稼働状態と主要メトリクスを確認可能にする。
- 少なくとも次のアーキテクチャ固有状態を確認可能にする。
  - Master Gatewayの状態・世代
  - 再同期中のGateway
  - プロトコル／Capability不一致
  - Simulation Coreの進行遅延
  - Config異常
  - Operation再送の増加
  - 保存・復旧状態
- 表示方法、ダッシュボード構成、アラートUIは現時点では固定しない。

## 決定論との関係

- ログ・監視・診断処理そのものがWorld Stateの結果へ影響してはならない。
- ログ出力タイミング、監視取得順、メトリクス収集スレッド等の実行差を世界結果の決定要因にしない。
- 状態ハッシュ診断は標準シミュレーションへ侵襲的な副作用を与えない設計とする。

## 今後決定が必要な事項

- 構造化ログの具体フォーマット
- ログレベルとイベント分類
- メトリクス体系
- アラート条件
- 状態ハッシュの粒度、対象、計算頻度、コスト上限
- 高度な決定論診断アドオンの具体仕様
- ログ保持Configのキー、既定値
- Admin Viewでの具体的な可視化方法
