# シミュレーション詳細度・集約遷移設計

## 確定方針

第190〜194問で扱った詳細度・個体化・集約・境界因果に関する方針は、すべて外部Configから選択可能とし、デフォルトは各問のC相当とする。

Configの具体的なキー名・形式・再読込方式は現時点では未決定とする。

### 第190問: 詳細シミュレーション領域

- Configにより、世界全域を常に同じ詳細度で計算する方式、必要地域のみ詳細化してその他を因果関係を維持した簡略シミュレーションとする方式、世界全域で可能な限り個体・物品・建物レベルの状態を保持しつつ更新頻度を大幅に落とす方式を選択可能とする。
- デフォルトはC相当とし、世界全域で可能な限り個体・物品・建物レベルの状態を保持しつつ、必要性に応じて更新頻度を下げる。
- デフォルトCであっても、全世界を30Hzで一律更新することを意味しない。

### 第191問: 詳細領域への昇格

- Configにより、詳細領域固定、必要時の決定論的昇格、将来必要になりそうな地域の予測的事前詳細化を選択可能とする。
- デフォルトはC相当とし、B相当の決定論的な昇格に加えて、将来必要になりそうな地域を予測して事前詳細化できる構成とする。
- 予測的事前詳細化が世界結果を処理速度・スレッド実行順・実行環境依存にしてはならない。

### 第192問: 詳細領域からの降格

- Configにより、一度詳細化した状態を保持し続ける方式、因果を失わない集約状態へ戻す方式、集約後も詳細状態を永久アーカイブして完全復元可能とする方式を選択可能とする。
- デフォルトはC相当とし、必要に応じて簡略状態へ降格可能でありながら、詳細状態そのものもアーカイブし、完全復元可能とする方向とする。
- 保存形式、アーカイブ粒度、保持期間、容量管理、復元手順は未決定とする。

### 第193問: 個体化・集約の一貫性

- Configにより、簡略状態からその時点で適当な個体を生成する方式、集約状態と整合する決定論的個体化方式、世界生成時点ですべての将来個体に恒久IDを割り当てる方式を選択可能とする。
- デフォルトはC相当とし、世界生成時点ですべての将来個体へ恒久IDを割り当てる方向とする。
- この恒久ID方針は住人だけに限定せず、どの種類の将来個体へ適用するかは今後決定する。
- 詳細化・再集約を繰り返しても人口、財産、資源、組織、履歴等が不自然に増減しないことを必須とする。

### 第194問: 領域境界をまたぐ因果

- Configにより、総量中心の簡略境界連携、システムごとの必要な因果連携、境界付近の常時完全詳細計算を選択可能とする。
- デフォルトはC相当とし、B相当の因果連携に加えて、境界付近を常に完全詳細計算する方向とする。
- 人口移動、物流、価格、情報、疾病、軍事、河川、大気、電力、通信等の必要な因果が詳細度の違いによって途切れてはならない。この列挙は網羅ではない。

## 共通要件

- すべての調整可能な数値・しきい値・範囲・更新頻度等は外部Config化する。
- 同一のWorld Seed、シミュレーションへ影響するConfig、同一操作・順序・適用時刻からは同一結果を得られる決定論・完全再現性の原則を維持する。
- 詳細化、降格、事前詳細化、アーカイブ、個体化、境界処理は、処理速度、OSスケジューリング、スレッド順序、Gateway数等に世界結果を依存させてはならない。
- Config選択によってシミュレーション精度・保持量・計算負荷・保存量は大きく変化し得るが、各モードの意味論は明示する。
- アドオンを前提とした具体的API・プラグイン機構は現時点では定義しない。

## 今後決定が必要な事項

- Config項目の具体名・型・許容値
- Config変更を起動時のみ許可するか、実行中変更も許可するか
- C相当デフォルト時の恒久ID対象範囲
- 予測的事前詳細化の決定論的な判定基準
- 詳細状態アーカイブの保存形式・容量管理・復元方式
- 境界付近の完全詳細領域の幅・形状・移動規則
- 詳細度ごとの更新頻度と30Hz Core計算との関係
