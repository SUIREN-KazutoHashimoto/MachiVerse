# 複数シミュレーションコア設計

## 1. 目的

MachiVerse は、1つのシミュレーションコアが担当する詳細シミュレーション範囲を固定し、シミュレーションコアを追加することで詳細にシミュレーションする世界領域を拡張できる構成を採用します。

複数コアは、利用者から一つの連続した世界として見える必要があります。コア分割は計算・運用上の境界であり、世界の因果関係を切断する境界として扱いません。

本構成ではデータベースを用意しません。そのため、世界状態の正本、世界要素の所有権、コア間移譲、重複・喪失防止は複数コア設計上の最重要事項として扱います。

## 2. 基本構成

- 1つのシミュレーションコアは固定された1つの詳細シミュレーション範囲を担当する。
- シミュレーションコアを追加することで、詳細シミュレーション対象領域を追加できる。
- 各シミュレーションコアには少なくとも1つのゲートウェイを用意する。
- コア間通信は論理メッシュ構造とする。
- コアは必要な別コアと直接通信可能な論理構造を持つ。
- 全コアが常時すべてのコアとの物理接続を維持することまでは要求しない。
- 実際の接続確立方式、接続維持方式、通信相手探索方式は今後定義する。

## 3. 論理メッシュ構造

コア間の通信トポロジはリング型ではなく論理メッシュ型とします。

```text
Core A ───── Core B
  │  \       / │
  │   \     /  │
  │    Core C   │
  │      │      │
Core D ──┴──── Core E
```

この図は全コア間の常時物理接続を意味しません。

論理メッシュの目的は、あるコアから別コアへ情報を送る際に、通信トポロジ上の中継コアを必須としないことです。世界上の因果関係、世界要素の移動、境界影響等の必要性に応じて、対象コアへ直接通信できることを基本とします。

地理的な隣接関係と通信可能関係を同一制約として固定しません。どのコア同士が常時接続するか、必要時のみ接続するかは別途定義します。

## 4. データベースを用いない原則

MachiVerse の本構成では、シミュレーション状態の正本を保持する中央DB・共有DBを用意しません。

したがって、次のような構成を採用しません。

- コア間で競合した正本状態を後からDBで解決する構成
- 世界要素の現在所有者をDBへ問い合わせることを必須とする構成
- コア障害・通信障害時にDBを唯一の正本として復旧する構成
- 複数コアが同じ世界要素を正本として保持し、DB側で最終決定する構成

世界状態の正本管理は、シミュレーションコア自身とコア間プロトコルの契約によって成立させます。

## 5. 正本所有権

### 5.1 基本原則

世界状態の各正本は、その時点で責任を持つシミュレーションコアが所有します。

同一の世界要素について、複数コアが同時に正本所有者として状態変更を確定してはなりません。

別コアが参照・計算補助のために複製情報を保持する場合でも、それを正本として扱いません。

### 5.2 所有権の一意性

所有権管理では少なくとも次を保証できる必要があります。

- 現在の正本所有者が一意であること。
- 旧所有者と新所有者が同時に正本更新権を持たないこと。
- 所有権移譲中に世界要素が二重生成されないこと。
- 所有権移譲中に世界要素が消失しないこと。
- 再送や通信重複によって同一移譲が二重適用されないこと。
- 通信到着順や処理速度差によって所有権結果が変わらないこと。

## 6. コア間で扱う情報の原則

コア間通信は、他コアの内部状態全体を共有するための分散共有メモリとして扱いません。

コア間では、世界境界を越えて成立させるために必要な情報をプロトコルで交換します。

現時点で必要となる通信カテゴリの概念は以下です。

- コア同士の識別・接続・互換性確認
- 担当領域に関する情報交換
- 境界付近で別コアの計算へ必要となる状態・影響の交換
- コアを越えて伝播する世界上の影響
- 世界要素が別コア担当範囲へ移動する際の所有権移譲
- World Timeに基づく適用時点・順序の識別
- 再送、重複排除、冪等性に必要な識別情報
- コアの接続・利用可能状態に関する情報

具体的な世界モデルが未確定のため、自然環境、住民、交通、物流等の個別通信モデルを本設計だけから確定しません。

## 7. 所有権移譲

世界要素があるコアの正本責任から別コアの正本責任へ移る場合、コア間プロトコルによる明示的な所有権移譲として扱います。

所有権移譲には少なくとも次の概念が必要です。

1. 移譲対象を一意に識別する。
2. 現在の正本所有者を識別する。
3. 移譲先コアを識別する。
4. 移譲対象の状態と、移譲を適用するWorld Time上の位置を識別する。
5. 移譲先が受入可能かを判断できる。
6. 移譲の確定点を識別できる。
7. 再送されても二重移譲にならない。
8. 中断時に正本が二重化・喪失しない。

移譲を何段階のハンドシェイクで実現するか、具体的に2-phase commit等を採用するかは未確定です。

## 8. 決定論との関係

複数コア構成でも、MachiVerse の決定論的再現性要件を維持します。

同一World Seed、同一のシミュレーションへ影響する設定、同一操作、同一初期状態、同一の世界上の因果入力である場合、以下の運用上の違いによって世界結果が変化してはなりません。

- コアごとの処理速度
- OS・スレッドスケジューリング
- コア間通信の実時間上の到着順
- ネットワーク遅延
- 再送回数
- 一時的な通信重複
- 物理的な接続確立タイミング

コア間通信の適用は、実時間での到着順ではなくWorld Time上の適用時点と決定的な識別・順序規則を基準とします。

具体的なWorld Time同期方式、待ち合わせ方式、遅延時の進行制御、決定的順序キーは今後定義します。

## 9. ゲートウェイとの関係

各コアには少なくとも1つのゲートウェイを用意します。

利用者はコアへ直接接続せず、ゲートウェイを通じて世界を参照・操作します。

現在接続中Gatewayの担当範囲外を参照する場合、現在側のMaster Gatewayが別コア側GatewayへのProxyとして情報を取得できます。

利用者が必要とするデータのうちProxy取得側が多くなる場合やGateway負荷状況から別Gatewayが適切な場合は、Master GatewayがGatewayハンドオーバーを調整します。

コア間の世界状態・所有権移譲と、利用者のGatewayハンドオーバーは別の責務として扱います。利用者接続先が切り替わっただけで世界状態の正本所有権が自動的に変更されたと見なしません。

## 10. プロトコル所有責任

コア間通信は `docs/protocols/core-core.md` を通信契約とします。

コア同士は同一コンポーネント種別であるため、プロトコル設計責任はシミュレーションコアが持ちます。

コア同士でコード、DLL、内部型、共有DTOライブラリを通信契約として共有しません。

## 11. 禁止事項

- 中央DB・共有DBをシミュレーション状態の正本として前提にすること
- 同一世界要素を複数コアが同時に正本として変更確定すること
- コア間通信の実時間到着順でシミュレーション結果を決めること
- 世界要素の所有権移譲を識別情報なしで行うこと
- 再送時に同一移譲を無条件で再適用すること
- 別コアの内部可変データへ直接アクセスすること
- 論理メッシュを理由に、全コア間の常時物理接続を必須要件として勝手に固定すること
- Gatewayの利用者ハンドオーバーとCoreの世界状態所有権移譲を同一処理として扱うこと

## 12. 今後決定が必要な事項

- コア識別子の形式
- 担当領域の具体的な表現
- コア探索・接続先発見方式
- 常時接続と必要時接続の使い分け
- コア追加・削除時の領域割当方法
- コア障害時の正本状態の扱い
- 所有権台帳を各コアがどのように保持するか
- 所有権照会方式
- 所有権移譲の具体的な状態機械
- 所有権移譲中の対象更新可否
- 移譲中断・タイムアウト時の復旧規則
- 境界状態の具体的な定義
- 境界影響の交換単位
- 遠隔コアへ届く影響の扱い
- World Time同期方式
- コア間の進行待ち合わせ方式
- 遅延メッセージの扱い
- 冪等性キー・重複排除方式
- コア間Protocolの物理通信方式
- シリアライズ形式
- 認証・相互認証
- 圧縮
- タイムアウト・再試行等の調整値

調整可能な数値を導入する場合は、コアが所有する外部Configから変更可能にします。
