# 支払手段・決済シミュレーション設計

## 1. 確定方針

標準では経済主体の資産を単一の「所持金」数値だけとして扱わず、社会・技術に応じた複数の支払手段を区別できるものとする。

- 物理的貨幣、預かり資産、口座的記録、信用による支払い等を社会・時代・技術に応じて表現できる。この列挙は確定済みの全支払手段ではない。
- 取引時に利用できる支払手段は、主体が保有・利用可能な資産、相手側の受容、制度、技術、アクセス可能性等によって異なり得る。
- 物理貨幣は必要に応じて物品所在・所有・運搬等の世界状態と接続できる。
- 記録型の資産・支払いは信用・債務、契約、金融機関等と接続できる方向とする。
- 標準では銀行間決済、清算網、詳細な決済インフラ等をC相当の最高詳細度まで必須としない。
- 将来アドオンによって、銀行間決済・清算網・詳細な決済インフラ等をC相当まで拡張できる余地を持たせる。
- アドオン対応を理由として標準実装の性能・決定論・現在の要件を損なう設計にはしない。
- 決済処理も決定論・完全再現性の原則に従う。

## 2. 今後決定が必要な事項

- 支払手段の標準分類
- 保有・移転・決済の状態表現
- 相手側の受容条件
- 物理貨幣の個体化・集約方針
- 金融機関・信用との接続
- C相当を可能にする将来アドオンとの境界。ただし具体的API・機構は現時点では定義しない
