# Diverと住人の紐付け設計

## 確定方針

第260〜264問について、以下を標準要件とする。

### Diverが操作する対象

- Diverは専用のプレイヤーEntityを生成するのではなく、世界内にすでに存在している通常の住人Entityへ紐付いて操作する。
- Diver参加のために新しい住人を生成する仕組みは標準では設けない。
- Diverが操作中であっても、その住人は通常の住人として、物理・社会・経済・法・健康・関係・生活その他の世界シミュレーション規則に従う。
- Diverだからという理由だけで無敵化、特別な移動、特別な所持、世界規則の無視等を許可しない。

### 参加時の住人選択

- Diverは既存住人の中から参加対象を選ぶ。
- 新規住人生成による参加は行わない。
- Diverは参加対象について大まかな要求・希望条件を提示できる。
- 要求例の具体項目や検索UIは現時点では固定しない。
- 世界内に条件を満たす対象が存在すること、権限上その対象へ参加できること、参加競合がないこと等は保証されない。
- 要求を満たす住人が見つかるかどうかは、その時点の世界状態・参加規則・権限・利用状況等によって決まり、要求が必ず叶う仕様にはしない。
- 任意の住人を無条件に奪取・上書きできる仕組みにはしない。

### 同一住人への複数Diver操作

- 原則として、一つの住人を同時に操作できるDiverは一人だけとする。
- 通常切断・エラー切断によって、その住人の操作Diverが別のDiverへ自動的に切り替わることはない。
- 切断後も、その住人と操作Diverの紐付けは維持される。
- 二重ログイン、再接続競合等で同一住人へ複数の能動操作主体が同時に成立しないようにする。
- 紐付け状態や競合管理の具体的な保存場所・プロトコル表現は今後決定する。

### 切断後の復帰

- Diverは再接続時にも同じDiver識別を使用する。
- 切断前に操作していた住人が存命であり、その紐付けが有効な限り、再接続後も同じ住人へ復帰する。
- 切断中も世界は進行し、住人は世界から消滅しない。
- 切断中の住人行動は、別途確定済みの「Diverが事前設定できる不在時行動優先方針」に基づいて世界シミュレーション側で処理される。
- 再接続時に切断時点へ世界を巻き戻さない。

### Diverが操作する住人の死亡

- Diverが操作していた住人が死亡した場合、その住人を同一個体として即時復活させない。
- 死亡した住人は通常の死亡処理に従い、遺体、相続、記録、家族・組織・社会への影響等を通常の世界因果として残す。
- 死亡後の再参加は、世界設定・参加規則・権限等に従って別の既存住人へ紐付く形を取り得る。
- この場合も新しい住人をDiver参加のためだけに生成しない。
- Diver識別自体は同一のものを継続して使用する。

## 設計上の区別

- 「Diver識別」と「現在操作中の住人Entity」は同一概念ではない。
- 通常の切断・再接続では、同じDiver識別と同じ住人Entityの紐付けを維持する。
- 住人の死亡等、世界上その個体を継続操作できない事象が発生した場合のみ、参加規則に従って同じDiver識別を別の既存住人へ紐付ける可能性がある。

## 今後決定が必要な事項

- Diverが指定できる大まかな要求・希望条件の具体範囲
- 希望条件に対する候補検索・選定方法
- 住人への参加可否を決める権限・世界側条件
- 紐付け状態の永続化・復旧方法
- Diver死亡後の再参加可能時期や制約
- 同一アカウント内で複数のDiver識別を許可するかどうか
