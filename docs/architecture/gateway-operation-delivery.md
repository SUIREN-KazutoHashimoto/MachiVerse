# Gateway操作配信・重複排除設計

## 確定方針

第215〜219問はすべてCを採用する。

### Operation ID

- 各外部操作には、Gateway間、Master Gateway、Simulation Core、再送を通して追跡可能なOperation IDを持たせる。
- 同一の論理操作を再送する場合、Operation IDを変更しない。
- Master切替や接続復帰によって同一操作へ別IDを付与し、別操作として扱うことを禁止する。
- Operation IDの具体的形式、生成規則、ビット幅等は今後決定する。

### End-to-End重複排除と冪等性

- 再送、切断復帰、Master切替、確認応答消失、結果再通知等が発生しても、同一Operation IDが世界状態へ複数回作用しないことをEnd-to-Endの標準要件とする。
- Gateway側で重複排除していても、それだけを唯一の安全性境界とはしない。Coreへ到達するまでの経路全体で重複を識別可能にする。
- Coreは世界状態の最終的な権威であり、同一論理操作の二重適用によって世界結果が変化しない設計とする。
- 重複記録の保持期間、保持形式、破棄条件等は今後決定する。

### Master世代 / Epoch

- Master Gatewayの選出ごとに、世代番号またはEpochに相当する識別情報を持たせる。
- Masterの正当性はSimulation Coreが管理する。
- 新しいMaster世代が成立した後、旧世代Masterから遅延して届いたバッチを新世代の正規入力として誤適用しない。
- Master世代の具体的表現、更新規則、選出時の通知手順等は今後決定する。

### 再送

- 操作やバッチを再送する場合、Operation ID、Batch IDその他の論理識別情報を保持したまま再送する。
- 確認応答が失われた場合でも、安全に同一内容を再送できることを標準要件とする。
- 再送回数、再送タイミング、到着順の違いが世界結果へ影響してはならない。
- 再送間隔、上限、タイムアウト、バックオフ等の調整可能な数値は外部Configで管理する。
- 再送アルゴリズムの具体方式は今後決定する。

### 複数Gatewayからの操作順序

- 各Gatewayは、自身が受け付けた有効操作について決定論的なローカル順序を構成する。
- 非Master GatewayはローカルバッチをMasterへ送る。
- Masterは自身のローカルバッチと他Gatewayから受信したローカルバッチを決定論的に統合し、Core向け最終バッチを構成する。
- Masterへの物理的な到着順、ネットワーク遅延、受信スレッド順をそのまま最終操作順として使用しない。
- 同一の有効操作集合であれば、Gateway台数、Master個体、ネットワーク遅延、受信スレッド順が異なっても、Coreへ渡る有効順序および世界結果を一致させる。
- ローカル順序キー、Gateway間統合キー、Batch IDの具体的構成は今後決定する。

## Coreとの責務境界

- Gatewayは認証・認可、外部要求レベルの集約・競合調停、順序構成、重複識別を担う。
- Master Gatewayは複数Gatewayをまたぐ外部要求レベルの最終統合を担う。
- Simulation Coreは世界状態と世界法則の最終的な妥当性判断および適用を担う。
- Gatewayでの競合解決結果がCoreの世界法則を上書きしてはならない。

## 決定論との関係

- Operation ID、Batch ID、Master世代、再送、重複排除、操作順序の処理は、処理速度、OSスケジューリング、スレッド完了順に依存してはならない。
- 同じ有効操作集合・順序・適用時刻がCoreへ入力される限り、Master切替や再送の有無で世界結果を変化させない。
- 保存・再開・リプレイに必要な外部操作履歴でも、同一論理操作を同じOperation IDとして追跡可能にする。

- Batch IDの形式・生成規則

- Gatewayローカル順序キー
- MasterでのGateway横断統合キー
