# 横断アーキテクチャ最終要件

## 確定方針

第275〜279問はすべてCを採用する。

## Q275: Admin操作の妥当性とCoreの状態整合性

- Admin Viewからの操作はGatewayを経由する。
- Admin操作としての権限、操作形式、対象、許可条件等の妥当性検証はGatewayの責務とする。
- CoreはAdminというUI上の役割を解釈してAdmin固有の権限判定を行わない。
- 一方でCoreは、すべての状態遷移に共通する世界状態の不変条件・整合性を維持する責務を持つ。
- GatewayがAdmin操作として妥当と判断したことを理由に、Coreが不整合な世界状態を無条件で生成してはならない。
- 「Admin操作として許可されるか」と「Coreの世界状態遷移として成立するか」を明確に分離する。

## Q276: 外部Operationの適用World Time

- GatewayおよびMaster Gatewayは、標準プロトコルの規則に従ってOperationの候補適用時刻・順序情報を形成する。
- Coreは現在のWorld Time、受付締切、Master世代、Operation ID、順序規則等に基づき、最終的な有効適用Stepを確定する。
- Gatewayへの物理的到着時刻やネットワーク遅延そのものを、そのまま世界状態の適用順序として扱わない。
- 同じ有効Operation集合と同じ論理条件では、通信速度、スレッド競争、Gateway数、Master個体等の違いだけで世界結果が変化してはならない。
- 遅延Operationの繰越・拒否等は既存のMaster failoverおよびdeadline規則と整合させる。

## Q277: World Timeの権威ある内部表現

- 権威あるシミュレーション時間軸は整数ベースのSimulation Stepとする。
- 標準の30HzはこのStep進行に対する標準設定として扱う。
- 秒、日時、表示時刻等は必要に応じてSimulation Stepから変換する。
- 社会・文化・時代依存の暦、時計、住人の時間認識は、Coreの権威あるSimulation Stepとは分離する。
- 浮動小数秒の累積を権威あるWorld Timeとして使用しない。
- Stepの具体的な整数型、epoch、変換精度等は詳細設計で決定する。

## Q278: Pause中のOperation

- Pause中もOperationの受信、認証、認可、妥当性確認、キュー保持等は可能とする。
- シミュレーションへ影響するOperationを、Pause中に進行していないWorld Timeへ曖昧に適用してはならない。
- シミュレーション影響OperationはResume後の明示的な有効Simulation Stepへ決定論的に割り当てる。
- シミュレーションへ影響しない運用操作は、必要に応じてPause中でも実行可能とする。
- Pause時間の長さ、受信順、処理速度等が世界結果へ非決定論的に影響してはならない。

## Q279: 通貨供給・金融政策

- 標準シミュレーションで、通貨発行、通貨供給量、発行主体および基本的な金融政策を扱う。
- 現代的な中央銀行制度を普遍的な前提としない。
- 通貨の発行主体、供給調整、信用との関係、制度的な管理方法等は社会・時代・制度の歴史的形成によって異なり得る。
- 通貨制度は形成・変化・競合・衰退し得る世界状態として扱う。
- 高度な金融市場モデル、高度な金融政策モデル等は将来アドオンで拡張可能とする。

## 横断的な位置付け

これらは個別機能ではなく、決定論、時間、権限境界、Gateway/Core責務、経済世界モデルに対する横断要件である。各コンポーネントの詳細設計およびプロトコル設計は、本書と既存の関連設計書の双方を満たす必要がある。

## 詳細設計へ持ち越す事項

- Coreが維持する世界状態不変条件の具体的一覧
- Operation候補適用時刻を表現する具体的なプロトコル項目
- Simulation Stepの整数型、epoch、秒・日時変換規則
- Pause中Operationキューの容量・期限等のConfig項目
- 通貨供給・金融政策の具体的なシミュレーションモデル
