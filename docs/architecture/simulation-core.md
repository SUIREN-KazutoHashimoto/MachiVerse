# シミュレーションコア設計

## 1. 目的

シミュレーションコアは、MachiVerse におけるシミュレーションそのものの実行責任を持つ領域です。

UI、通信方式、管理画面、外部クライアント数などの外部事情から独立し、シミュレーション状態とルールを一貫して扱えることを目的とします。

## 2. 主な責務

シミュレーションコアは、少なくとも以下の機能責務を持ちます。

- シミュレーション状態の保持
- シミュレーション時間の進行
- エージェント状態の保持と更新
- 環境状態の保持と更新
- シミュレーションルールの適用
- 状態遷移の実行
- 内部イベントの処理
- 外部から受け付けた有効な操作要求の反映
- 外部参照用の状態提供
- 実行状態の管理

## 3. 責務外

以下はシミュレーションコアの直接責務としません。

- Web 画面やデスクトップ画面の描画
- UI レイアウト
- 外部クライアントとの直接接続管理
- HTTP、WebSocket 等の具体的な外部通信方式
- 一般利用者のセッション管理
- 管理画面そのものの実装
- 外部向けの負荷分散
- UI 用データの装飾や表示形式への変換

## 4. 主要機能

### 4.1 実行状態管理

シミュレーションが現在どの実行状態にあるかを管理します。

想定される概念として、開始前、実行中、一時停止中、停止中などがあります。ただし、具体的な状態一覧と状態遷移規則は今後定義します。

### 4.2 時間進行

シミュレーション内部の時間を進めます。

時間進行方式、Tick の有無、固定時間刻み・可変時間刻み・イベント駆動などの方式は現時点では未確定です。

### 4.3 エージェント管理

シミュレーションに存在するエージェントの状態を管理します。

具体的なエージェント種別、属性、生成・消滅条件、更新頻度、所属関係などは今後定義します。

### 4.4 環境管理

エージェントが存在・行動するシミュレーション環境の状態を管理します。

環境が空間、ネットワーク、グリッド、地理情報、論理空間などのどの形式を取るかは現時点では未確定です。

### 4.5 ルール実行

エージェントや環境へ適用されるシミュレーションルールを実行します。

ルールは UI や通信方式に依存させず、シミュレーションの意味論として定義します。

### 4.6 内部イベント処理

シミュレーション内部で発生する状態変化や通知をイベントとして扱う場合、その生成・処理順序・反映責任を管理します。

イベント方式を採用するか、どの粒度で採用するかは今後の詳細設計事項です。

### 4.7 外部操作の受理

ゲートウェイから渡された操作要求を、シミュレーション上有効か判定したうえで処理します。

外部から届いた要求をそのまま状態へ反映するのではなく、最終的なシミュレーション上の整合性判断はコア側が持つことを基本とします。

### 4.8 状態参照

外部表示や管理のために必要なシミュレーション状態を提供します。

外部利用者が内部データ構造を直接参照・変更する形にはせず、公開可能な境界を設けます。

## 5. データ所有権

シミュレーションの正本となる状態は、原則としてシミュレーションコアが所有します。

ビューやゲートウェイが保持する表示用キャッシュや転送用データは、シミュレーション状態の正本とはみなしません。

## 6. 他領域との関係

### ゲートウェイとの関係

- 外部からの要求はゲートウェイを経由して受け取る。
- 外部公開用データはゲートウェイへ提供する。
- ゲートウェイのスケール方式をコアが直接知る必要はない。

### ビューとの関係

- 直接依存しない。
- ビュー固有の表示状態を保持しない。

### 管理ビューとの関係

- 直接依存しない。
- 管理操作はゲートウェイ側の管理境界を経由して受け取る。

## 7. 超大規模化における設計要件

シミュレーションコアは将来的に以下を検討可能な構造を保ちます。

- 状態更新の並列化
- 処理単位の分割
- 一部処理の分散化
- 大量エージェントの効率的な保持
- 状態参照と状態更新の競合低減
- スナップショット取得
- 再現性の確保
- ボトルネック計測

具体的な方式は、性能目標とシミュレーション要件が確定した後に決定します。

## 8. 禁止する依存

- UI フレームワークへの依存
- 管理画面への依存
- 外部通信プロトコルをシミュレーションロジックへ直接組み込むこと
- ビュー都合の DTO や画面構造をコアのドメインモデルとして扱うこと
- 外部層からコア内部の可変状態を直接変更させること

## 9. 今後決定が必要な事項

- エージェントモデル
- 環境モデル
- 時間進行モデル
- 更新順序
- 並列実行単位
- 分散実行の有無
- 決定性・再現性要件
- 乱数管理方式
- スナップショット方式
- 永続化との境界
- 外部操作の整合性規則
- 外部参照用データの粒度
