# Config意味論・変更適用・互換性設計

## 確定方針

第210〜214問は以下で確定する。

- 第210問: C
- 第211問: C
- 第212問: Cを基本とし、起動時に不整合がある場合は起動しない
- 第213問: カスタム方針
- 第214問: 下位互換を設け、古いConfigで不足する項目はデフォルト値をConfigファイルへ追加する

## Config分類

- 少なくとも「シミュレーション結果へ影響するConfig」と「表示・運用のみで世界結果へ影響しないConfig」を区別する。
- Config項目は必要に応じて、再起動必須、World再生成必須、実行中変更可能等の変更可能性を明示する。
- シミュレーション影響Configは再現条件の一部として扱う。
- 調整可能な数値・閾値・頻度・範囲等は外部Configへ置くという共通原則を維持する。

## 実行中のConfig変更

- Configファイルが変更された瞬間に各処理が個別に新値を読み始める方式にはしない。
- 実行中変更可能なConfigは、明示的な適用境界で一括反映する。
- 世界結果へ影響するConfig変更はWorld Timeまたは適用ステップへ結び付けて履歴化し、保存・再開・リプレイ時にも同じ時点で再適用できるようにする。
- 具体的な監視方式、リロード方式、適用APIは現時点では固定しない。

## Config検証と起動可否

- Configは起動時および変更時に、型、許容範囲、相互制約等を検証する。
- 不正な項目のみを無視して部分適用する方式にはしない。
- 変更セットは全体として検証し、一項目でも不整合があればその変更セットを適用しない。
- 実行中の変更が不正な場合は、直前の有効なConfigを維持する。
- 起動時にConfig全体として不整合が存在する場合は、Simulation Coreまたは該当コンポーネントを起動しない。
- 何を「不整合」と判定するかの具体的制約一覧は各Config設計で定義する。

## コンポーネント間のConfig責務

- Core、Gateway、General View、Admin Viewは、それぞれ自身のConfigのみを所有する。
- 他コンポーネントの挙動へ直接影響させる目的の共有Configファイルは用意しない。
- 他コンポーネントに影響する必要情報は、Configファイルの共有ではなく、Coreにより近い側のコンポーネントが自身の責務として配布する。
- 配布はコンポーネント間プロトコルを通じて行い、共有ファイルや他コンポーネントConfigへの直接参照を暗黙の通信路にしない。
- どの情報をどのプロトコルで配布するか、その同期・更新・失敗時挙動は各プロトコル設計で決定する。
- 「Coreに近い側」が持つ情報であっても、それを下流コンポーネントのConfigファイルとして扱うことはしない。

## Configの下位互換

- Configには下位互換を設ける。
- 古いConfigを読み込んだ際、現行版で追加された項目が不足しているだけであり互換性を維持できる場合は、その項目のデフォルト値を使用する。
- その場合、不足していた項目と採用したデフォルト値をConfigファイルへ追加し、現行構成へ補完する。
- 古いConfigだからという理由だけで起動拒否しない。
- ただし、単なる項目不足ではなく値の不整合や意味的に解釈不能な状態がある場合は、前節の検証ルールに従い起動または変更適用を拒否する。
- Configファイルの具体的な形式、バージョン表現、書き戻し方法、原子的更新方法は未決定とする。

## 再現性との関係

- シミュレーション影響Configの有効値は、ファイルに元から存在したかデフォルト補完されたかにかかわらず、実際に適用された値を再現条件として扱う。
- 保存・リプレイでは、適用済みのシミュレーション影響Configと、その実行中変更の適用時点を再現可能にする。
- Config補完処理そのものがOSスケジューリング、処理速度、Gateway数等によって変化してはならない。

## 今後決定が必要な事項

- Configファイル形式と配置
- Configのバージョン表現
- 各項目の分類方法
- 起動時検証と実行中変更検証の具体的制約
- デフォルト値の定義元
- 古いConfigへのデフォルト値書き戻し方法と失敗時挙動
- 配布対象となるコンポーネント間情報と各プロトコル上の表現
