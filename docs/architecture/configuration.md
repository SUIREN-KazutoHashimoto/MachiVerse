# 外部Config設計

## 1. 目的

MachiVerse では、システム動作を調整する各種数値をソースコードへ固定値として埋め込まず、外部Configから変更可能にします。

この方針はシミュレーションコア、ゲートウェイ、一般ビュー、管理ビューの全コンポーネントに適用します。

## 2. 基本原則

- 調整可能な数値は外部Configから供給する。
- ソースコード内へ運用値・性能調整値・時間値・件数上限値等を直接固定しない。
- 各コンポーネントは、自身が責任を持つ数値設定を自身のConfigで所有する。
- 他コンポーネントのConfigファイルを直接参照しない。
- コンポーネント間でConfigファイルを共有しない。
- コンポーネント間契約に関わる数値の意味は、対象プロトコル設計書にも定義する。
- Configの具体的なファイル形式、配置方式、読み込み方式は現時点では未確定とする。

## 3. 現時点で確定している基準値

### 3.1 シミュレーションコア

シミュレーション計算頻度の基準値は **30Hz** です。

ただし、30Hzをソースコードへ固定値として埋め込まず、シミュレーションコアの外部Configから変更可能にします。

シミュレーションコアはマルチスレッド実行を前提とし、使用可能なスレッド数の上限は **16スレッド** とします。

実際に使用するスレッド数は、シミュレーションコアの外部Configから変更可能にします。16を超える設定値の扱いは、設定値検証仕様で明確に定義します。

### 3.2 ゲートウェイ

ゲートウェイがコアの計算・通信間隔の揺らぎを吸収するために設ける遅延バッファの基準値は **1秒** です。

ただし、1秒をソースコードへ固定値として埋め込まず、ゲートウェイの外部Configから変更可能にします。

## 4. Configの所有責任

各設定値は、その値を実際に使用して動作を決定するコンポーネントが所有します。

| 設定例 | 所有コンポーネント |
|---|---|
| シミュレーション計算頻度 | シミュレーションコア |
| シミュレーションコア使用スレッド数 | シミュレーションコア |
| シミュレーションコア最大使用スレッド数 | シミュレーションコア |
| ゲートウェイ遅延バッファ時間 | ゲートウェイ |
| ゲートウェイのキャッシュ関連数値 | ゲートウェイ |
| ゲートウェイの流量制御関連数値 | ゲートウェイ |
| 一般ビューの表示更新関連数値 | 一般ビュー |
| 管理ビューの表示・監視関連数値 | 管理ビュー |

この表にない将来の数値設定も、同じ原則で所有コンポーネントを決定します。

## 5. コンポーネント分離との関係

MachiVerse はコンポーネント間のコード依存を禁止しているため、Configについても同様に独立性を維持します。

例えば、ゲートウェイがシミュレーションコアのConfigファイルを直接読み取ることは禁止します。ゲートウェイが知る必要のある情報がコンポーネント間契約に含まれる場合は、コア・ゲートウェイ間プロトコルを通じて扱います。

これにより、各コンポーネントは自身のConfigだけを変更・管理でき、別コンポーネントの実装・設定ファイルとの競合を避けられます。

## 6. 数値の分類

外部Config化の対象には、少なくとも以下のような数値を含みます。

- 実行頻度
- 使用スレッド数
- 最大使用スレッド数
- 時間間隔
- 遅延時間
- タイムアウト
- キャッシュ保持時間
- バッファ量
- 件数上限
- サイズ上限
- 同時接続数等の制限値
- 再試行回数・間隔
- 流量制御値
- 表示更新頻度
- 監視間隔
- その他、運用・性能・シミュレーション挙動を調整する数値

具体的な設定項目は各コンポーネントの詳細設計で追加します。

## 7. 例外

数値リテラルがすべてConfig対象になるわけではありません。

アルゴリズム上の数学的定数、配列インデックス処理など、設定値として意味を持たない実装上の数値は対象外とできます。

判断基準は「環境、負荷、運用方針、シミュレーション条件等によって変更する可能性がある値か」です。変更可能性がある場合は外部Configを使用します。

## 8. Config変更時の扱い

Config値を実行中に動的反映するか、起動時のみ読み込むか、変更時に再起動を必要とするかは設定項目ごとに今後定義します。

Config値の妥当性検証、範囲、単位、既定値、必須・任意、異常値入力時の動作も各設定項目の詳細設計で定義します。

シミュレーションコアのスレッド数については、少なくとも **1以上16以下** の範囲を有効値とする方針です。実行中の動的変更を許可するかは未確定です。
