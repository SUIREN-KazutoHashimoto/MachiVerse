# ビュー設計

## 1. 目的

ビューは、一般利用者が MachiVerse のシミュレーション状態を閲覧し、許可された操作を行うための利用者向け領域です。

ビューは表示と利用者操作に集中し、シミュレーションロジック、通信基盤、運用管理ロジックを自身の責務として持ちません。

## 2. 主な責務

ビューは、少なくとも以下の機能責務を持ちます。

- 一般利用者向け画面の表示
- シミュレーション状態の可視化
- 利用者操作の受付
- ゲートウェイへの要求送信
- ゲートウェイから受け取ったデータの表示
- 表示用状態の管理
- 読み込み中・失敗・再接続など利用者向け状態の表示
- 利用者が理解できる単位への情報整理

## 3. 責務外

以下はビューの直接責務としません。

- シミュレーション状態の正本管理
- エージェント状態の直接更新
- シミュレーション時間の進行
- シミュレーションルールの判定
- シミュレーションコアへの直接接続
- 外部接続の負荷分散
- 管理者専用の運用操作
- システム全体の監視・障害対応

## 4. 主要機能

### 4.1 シミュレーション状態表示

ゲートウェイから取得したシミュレーション情報を一般利用者へ表示します。

どの情報をどの粒度で表示するか、どの程度リアルタイム性を要求するかは今後決定します。

### 4.2 可視化

数値、一覧、地理・空間表現、グラフ、状態表示など、シミュレーション内容に適した方法で情報を可視化します。

具体的な UI 形式や可視化技術は未確定です。

### 4.3 利用者操作受付

一般利用者が実行可能な操作を受け付けます。

ビュー側では入力補助や基本的な形式確認を行えますが、シミュレーション上の最終的な妥当性判断はシミュレーションコア側に委ねます。

### 4.4 表示用状態管理

画面選択状態、表示範囲、フィルタ、並び順、開閉状態など、表示のためだけに必要な状態を管理します。

これらをシミュレーションの正本状態と混同しません。

### 4.5 通信状態表示

ゲートウェイとの通信状態に応じて、読み込み中、切断、再試行中、取得失敗などを利用者へ適切に表示します。

### 4.6 大量データ表示への対応

超大規模シミュレーションでは、コアが保持する全情報をそのまま一度に表示できない可能性があります。

そのため、将来的に以下を検討できる設計とします。

- 表示対象の絞り込み
- ページング
- 表示範囲単位の取得
- 集約値の表示
- 詳細度の切り替え
- 更新頻度の調整

具体的な方式は、シミュレーション対象と UI 要件が決まった後に定義します。

## 5. データ所有権

ビューが所有するのは、原則として表示・操作に必要な一時状態です。

ゲートウェイから取得したシミュレーションデータを保持する場合でも、それはシミュレーション状態の正本ではありません。ビュー上の状態とコア上の状態が異なる場合、正本はシミュレーションコア側です。

## 6. 他領域との関係

### ゲートウェイとの関係

- 外部データ取得はゲートウェイを通じて行う。
- 一般利用者の操作要求をゲートウェイへ送る。
- 通信方式の詳細はゲートウェイ側との公開契約に従う。

### シミュレーションコアとの関係

- 直接依存しない。
- コア内部の型やデータ構造を UI から直接参照しない。

### 管理ビューとの関係

- 一般利用者向け機能と管理者向け機能を混在させない。
- 共通 UI 技術を利用する可能性はあっても、権限・責務は別領域として扱う。

## 7. 超大規模化における設計要件

- 全シミュレーション状態の常時取得を前提にしない。
- 画面更新頻度をシミュレーション更新頻度と安易に一致させない。
- 大量データを受け取った際にも UI が操作不能にならない構造を検討する。
- 表示要求がゲートウェイやコアへ過剰な負荷を与えないこと。
- 利用者数の増加に伴う負荷を、ビュー単体またはゲートウェイと協調して制御可能にすること。

## 8. 禁止する依存・実装

- シミュレーションコアへの直接接続
- シミュレーション内部状態の直接変更
- シミュレーションルールの UI 側への複製
- 管理者専用機能を一般ビューへ無条件で混在させること
- 表示用キャッシュを正本として扱うこと

## 9. 今後決定が必要な事項

- ビューの利用者像
- 提供画面一覧
- 表示対象データ
- 利用者が可能な操作
- UI 技術スタック
- リアルタイム性要件
- データ取得単位
- 大量データの可視化方式
- オフライン・切断時の挙動
- アクセシビリティ要件
- 対応端末・対応ブラウザ等の実行環境
