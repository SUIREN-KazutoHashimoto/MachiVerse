# ビュー設計

## 1. 目的

ビューは、一般利用者が MachiVerse のシミュレーション状態を閲覧するための利用者向け領域です。

一般ビューはリードオンリーとし、シミュレーション状態を変更する機能を持ちません。シミュレーションコアへ直接接続せず、すべてのデータ取得をゲートウェイ経由で行います。

## 2. 主な責務

- 一般利用者向け画面の表示
- シミュレーション状態の可視化
- ゲートウェイへの参照要求送信
- ゲートウェイから受け取ったデータの表示
- 表示用状態の管理
- 読み込み中・失敗・再接続など利用者向け状態の表示
- 利用者が理解できる単位への情報整理

## 3. 責務外

- シミュレーション状態の正本管理
- エージェント状態の更新
- シミュレーション時間の進行
- シミュレーションルールの判定
- シミュレーションコアへの直接接続
- シミュレーション状態変更要求の送信
- 管理操作
- 外部接続の負荷分散
- システム全体の監視・障害対応

## 4. 主要機能

### 4.1 シミュレーション状態表示

ゲートウェイから取得したシミュレーション情報を一般利用者へ表示します。

一般ビューが参照する情報は、原則としてゲートウェイが保持する参照用キャッシュを通じて提供されます。

### 4.2 可視化

数値、一覧、地理・空間表現、グラフ、状態表示など、シミュレーション内容に適した方法で情報を可視化します。

具体的な UI 形式や可視化技術は未確定です。

### 4.3 表示用操作

一般利用者による操作は、表示内容を変更する UI 操作に限定します。

例として、表示範囲、フィルタ、並び順、選択対象、詳細度などがあります。これらはビュー内部の表示状態またはゲートウェイへの参照条件であり、シミュレーション状態の変更を意味しません。

### 4.4 表示用状態管理

画面選択状態、表示範囲、フィルタ、並び順、開閉状態など、表示のためだけに必要な状態を管理します。

これらをシミュレーションの正本状態と混同しません。

### 4.5 通信状態表示

ゲートウェイとの通信状態に応じて、読み込み中、切断、再試行中、取得失敗などを利用者へ適切に表示します。

### 4.6 大量データ表示への対応

超大規模シミュレーションでは、全情報を一度に表示しないことを前提とします。

将来的に以下を検討できます。

- 表示対象の絞り込み
- ページング
- 表示範囲単位の取得
- 集約値の表示
- 詳細度の切り替え
- 更新頻度の調整

## 5. データ所有権

ビューが所有するのは表示に必要な一時状態のみです。

ゲートウェイから取得したシミュレーションデータは参照用であり、正本ではありません。正本はシミュレーションコア側にあります。

## 6. 他領域との関係

### ゲートウェイ

- 一般ビューはゲートウェイにのみアクセスする。
- データ取得はゲートウェイの公開済み読み取り境界を通じて行う。
- シミュレーション状態変更要求を送信しない。

### シミュレーションコア

- 直接依存しない。
- 直接接続しない。
- コア内部の型やデータ構造を参照しない。

### 管理ビュー

- 一般利用者向け機能と管理者向け機能を混在させない。
- コアへ影響を与える操作は管理ビュー側の責務とする。

## 7. 超大規模化における設計要件

- 全シミュレーション状態の常時取得を前提にしない。
- 画面更新頻度をシミュレーション更新頻度と安易に一致させない。
- 大量データ受信時にも UI が操作不能にならない構造を検討する。
- 一般ビューからの参照要求がコアへ直接波及しないこと。
- 利用者数の増加は主としてゲートウェイ層で吸収できる構成とする。

## 8. 禁止する依存・実装

- シミュレーションコアへの直接接続
- シミュレーション状態の変更要求
- シミュレーション内部状態の直接変更
- シミュレーションルールの UI 側への複製
- 管理者専用機能の混在
- 表示用データやゲートウェイキャッシュを正本として扱うこと

## 9. 今後決定が必要な事項

- ビューの利用者像
- 提供画面一覧
- 表示対象データ
- UI 技術スタック
- リアルタイム性要件
- データ取得単位
- 大量データの可視化方式
- オフライン・切断時の挙動
- アクセシビリティ要件
- 対応端末・対応ブラウザ等の実行環境
