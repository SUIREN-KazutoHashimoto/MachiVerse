# 歴史記録設計

## 1. 目的

本書は、MachiVerse において重要な過去の出来事を世界史として記録し、世界の真の履歴と住人・組織が保持する記録・伝承・認識を区別するための要件を整理します。

## 2. 確定事項

- 現在状態だけでなく、世界史として意味のある重要な出来事を歴史的イベントとして記録できるものとする。
- 出生、死亡、家族関係の変化、戦争、国家・組織の成立や消滅、発明、建設、災害等は記録対象の候補とするが、標準で記録する具体的一覧は今後定義する。
- 全30Hz状態や全内部変化を永久保存することは標準要件としない。
- Simulation Core が再現可能な世界の真の履歴と、住人・組織が保持する文書、記録、伝承、噂、認識等は別物として扱う。
- 住人・組織側の歴史認識は不完全・誤り・欠落を含み得るものとし、`information-communication-simulation.md` の情報・認識モデルと整合させる。
- MachiVerse は完全再現性を持つため、真の過去を再構築する手段が存在することを前提に、歴史記録機能の処理・実装優先度は他の中核シミュレーション要件よりやや低く扱う。
- ただし、完全再現性を理由として歴史記録という要件自体を削除しない。世界史の検索・提示・参照等に価値があるため、標準機能として成立する余地を保持する。
- 歴史記録の生成・分類等に確率的要素を含める場合も、MachiVerse の決定論・完全再現性の原則に従う。

## 3. 真の履歴と世界内の記録

Simulation Core が扱う実際の世界状態・出来事と、世界内の住人や組織が知る歴史を同一視しません。

住人・組織側の記録は、当時利用可能だった情報、観測、通信、文書、伝承等に基づくため、不完全・偏り・誤り・欠落があり得ます。一方、シミュレーションの真の履歴は完全再現性の条件が揃えば再構築可能であることを前提とします。

## 4. 記録粒度

標準では、歴史的意味を持つ出来事をイベント単位等で記録する方向とします。

30Hzごとの全状態スナップショットや全内部計算結果を永久保持する方式は標準要件としません。どの出来事を重要と判定するか、どの程度の要約・関連付けを行うかは今後定義します。

## 5. 優先度

MachiVerse の標準シミュレーションは、同一の World Seed、シミュレーションへ影響する Config、操作列・順序・適用時刻等から完全再現できることを前提とします。

このため、真の履歴を補助的に保存する仕組みは、住人、生態、経済、自然、社会制度等の中核的な世界状態を成立させる処理より実装・最適化の優先度をやや低く扱えます。

ただし、再現を毎回実行せずに世界史を参照する用途、ViewやAdministration Viewでの履歴確認、世界内の記録との比較等には独自の価値があるため、履歴記録を不要とはしません。

## 6. 今後決定が必要な事項

- 標準で記録する歴史イベントの具体的な種類
- イベントの重要度・記録対象判定
- イベント間の因果・関連付けを保持するか
- 履歴保持期間・圧縮・要約方式
- 完全再現による再構築と保存履歴の役割分担
- View / Administration View からの履歴参照要件
- 世界内の文書・記録・伝承との接続
- 事前歴史シミュレーションの履歴をどこまで保持するか
- 大規模世界での検索・索引・保存コスト
- 標準モデルと将来アドオン拡張の具体的な境界
