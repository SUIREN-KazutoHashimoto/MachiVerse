# Gateway Masterフェイルオーバー設計

## 確定方針

第220〜224問はすべてCを採用する。第222問については、通常のMaster再選出だけでなくライブマイグレーションに耐える設計を標準要件に含める。

### Master候補条件

- CoreはMaster Gatewayを有効かつ接続中のGateway群から選出する。
- 候補は単に接続しているだけではなく、プロトコル互換性、必要能力、同期状態その他Masterとして安全に動作するための条件を満たしていなければならない。
- 候補資格の具体的条件は今後プロトコル設計で定義する。
- Master選出結果そのものが同一の有効操作集合から得られる世界結果を変化させてはならない。

### 失敗検知

- Masterの失敗・応答不能は接続断だけでなく、ハートビート、応答遅延または同等の生存性確認によって検知可能とする。
- 失敗判定時間、監視間隔、再選出条件等の調整可能な値は外部Configで管理する。
- 一時的な遅延と実際の失敗を区別できる設計とする。
- 生存性判定の具体的アルゴリズムは現時点では固定しない。

### Master世代と切替

- Master選出ごとにCoreが管理する世代／Epochを持つ。
- 新しい世代が確定した後、旧世代Masterから遅延到着したMaster権限付きバッチを新世代の正規入力として誤適用しない。
- 未完了バッチ、確認応答待ち、再送中Operation等は新世代へ安全に引き継げるようにし、操作消失と二重適用を防止する。
- 切替設計は障害時フェイルオーバーだけでなく、計画的なMaster Gatewayのライブマイグレーションにも耐えなければならない。
- ライブマイグレーション中も、同じ論理OperationのOperation IDを維持し、重複排除・冪等性の保証を継続する。
- ライブマイグレーションの具体的な状態転送方式、切替ハンドシェイク、無停止保証範囲は今後決定する。

### バッチ受付締切

- World Time／適用ステップごとに操作バッチの受付締切を設ける。
- 締切までに確定した操作を当該適用対象として扱う。
- 締切、受付猶予、遅延判定等の調整可能な値は外部Configで管理する。
- 判定結果は同一再現条件で決定論的でなければならない。
- ネットワーク到着順や受信スレッド順だけで世界結果を決定しない。

### 締切後の操作

- 締切後に到着した操作を過去World Stateへ遡及適用して既確定状態を書き換えない。
- 遅延操作はプロトコル上で明示的に分類し、次以降の適用ステップへの繰越、期限切れ拒否、操作種別ごとの規則等から決定論的に扱う。
- 具体的な操作種別別ポリシーは今後定義する。
- 再送による遅延到着の場合もOperation ID／Batch ID等を用いて重複適用を防止する。

## 決定論と可用性

- Master Gatewayの個体、Master世代、再選出回数、ライブマイグレーション実施有無は、同一の有効操作集合・順序・適用時刻から得られる世界結果を変化させてはならない。
- フェイルオーバーやライブマイグレーションは可用性上の状態遷移であり、世界法則上のイベントとして暗黙に作用させない。
- Gatewayの障害復旧によってOperationが失われたり二重適用されたりしないことをEnd-to-Endで保証する。

## 今後決定が必要な事項

- Master候補資格の具体的能力・同期条件
- 生存性確認方式
- Epochの表現と配布方法
- ライブマイグレーション時の状態引継ぎ方式
- 未完了Batch／Operationの所有権切替規則
- バッチ受付締切と猶予のConfig項目
- 遅延Operationの種別別処理規則
