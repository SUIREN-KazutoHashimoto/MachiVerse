# 公的記録・身元・証明書シミュレーション設計

## 1. 確定方針

標準では社会制度がSimulation Core上の真の本人情報・世界事実を直接参照できるとは仮定せず、社会・時代に応じた記録・証明制度を世界状態として扱う。

- 住民登録、出生記録、所有記録、許可証、旅券的文書等の公的・組織的記録が存在し得る。この列挙は確定済みの全記録ではない。
- Core上の実在人物・事実と、制度が保持する記録内容を分離する。
- 記録は未登録、誤記、古い情報、虚偽、紛失等によって現実と一致しない場合がある。
- 記録・証明書は行政、所有・権利、資格・免許、移住・国境、司法、契約、アクセス権等と接続する。
- 社会・時代によって記録制度の存在・精度・普及範囲が異なり得るため、現代的な身分証明制度を普遍的前提としない。
- 標準では詳細な戸籍・登記制度、文書番号体系、発行更新手続、偽造検査等をC相当の最高詳細度まで必須としない。
- 将来アドオンによって、それらをC相当まで拡張できる余地を持たせる。
- アドオン対応を理由として標準実装の性能・決定論・現在の要件を損なう設計にはしない。
- 記録生成・照合等に確率的要素を含む場合も決定論・完全再現性の原則に従う。

## 2. 今後決定が必要な事項

- 公的・組織的記録の標準表現
- 人物・物件・権利等との参照関係
- 発行・更新・失効・紛失の扱い
- 記録と実世界事実の不一致処理
- 記録へアクセスできる主体・権限
- C相当を可能にする将来アドオンとの境界。ただし具体的API・機構は現時点では定義しない
