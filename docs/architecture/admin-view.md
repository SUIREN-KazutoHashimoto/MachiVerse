# 管理ビュー設計

## 1. 目的

管理ビューは、MachiVerse の運用者・管理者が、シミュレーションおよびシステム全体の状態を監視し、許可された管理操作を実行するための領域です。

一般利用者向けのビューとは、利用目的、権限、操作の影響範囲が異なるため、別の責務境界として扱います。

## 2. 主な責務

管理ビューは、少なくとも以下の機能責務を持ちます。

- シミュレーション実行状態の監視
- システム稼働状態の監視
- 管理者向け操作の受付
- ゲートウェイへの管理要求送信
- 管理情報・診断情報の表示
- 障害・異常状態の表示
- 負荷・処理状況の可視化
- 運用上必要な設定情報の表示および変更操作の入口
- 監査可能な管理操作を行うための UI 境界

## 3. 責務外

以下は管理ビューの直接責務としません。

- シミュレーションルールそのものの実装
- シミュレーション状態の正本管理
- エージェント状態の直接変更
- シミュレーションコアへの直接接続
- 認証・認可ロジックの最終判定
- 負荷分散や接続ルーティングの実装
- 一般利用者向け表示機能の主担当

## 4. 主要機能

### 4.1 シミュレーション実行状態監視

シミュレーションが稼働中か、停止中か、異常状態かなど、運用上必要な実行状態を確認できるようにします。

具体的な状態一覧はシミュレーションコア側の実行状態設計に合わせて定義します。

### 4.2 システム状態監視

シミュレーションコアだけでなく、ゲートウェイなど周辺領域も含めて運用状態を把握できることを目標とします。

監視対象として想定される情報には以下があります。

- 稼働・停止状態
- 処理遅延
- エラー発生状況
- 接続数
- 要求量
- シミュレーション処理負荷
- リソース使用状況

具体的なメトリクスは今後定義します。

### 4.3 管理操作

シミュレーションやシステムに対する管理操作を受け付けます。

将来的に考えられる操作例として、開始、停止、一時停止、再開、設定変更などがありますが、実際に提供する操作は要件確定後に定義します。

### 4.4 設定管理

運用中に変更可能な設定が存在する場合、その確認・変更を行う UI を提供します。

どの設定を動的変更可能にするか、変更時に再起動が必要か、変更履歴を残すかなどは今後の設計事項です。

### 4.5 障害・異常表示

システム内で発生した異常や、運用者が対応すべき状態を分かりやすく表示します。

単なるエラーメッセージ表示だけでなく、どの領域で何が起きているかを追跡可能にすることを目標とします。

### 4.6 診断情報表示

性能問題や障害調査に必要な診断情報を閲覧できるようにします。

ただし、管理ビュー自身が診断データの正本になるのではなく、各領域から取得した情報を表示する立場とします。

### 4.7 管理操作の監査

影響範囲の大きい管理操作について、誰が、いつ、何を行ったかを追跡できる仕組みを配置可能にします。

具体的な監査ログ方式は今後決定します。

## 5. データ所有権

管理ビューが所有するのは、画面表示や操作途中の UI 状態です。

シミュレーション状態、運用設定、メトリクス、監査情報などの正本は、それぞれを管理する領域側に置きます。管理ビュー上に保持する情報は参照用または一時的な表示用データとして扱います。

## 6. 他領域との関係

### ゲートウェイとの関係

- 管理操作はゲートウェイを経由して送信する。
- 管理状態・診断情報はゲートウェイ経由で取得する。
- 管理者向け境界は一般利用者向け境界と論理的に分離する。

### シミュレーションコアとの関係

- 直接依存しない。
- コアの管理可能操作は、公開された管理境界を通じて実行する。

### ビューとの関係

- 一般利用者向け UI と管理者向け UI の責務を分離する。
- 同じ技術基盤を使う場合でも、権限・機能・公開範囲を同一視しない。

## 7. 超大規模化における設計要件

- 監視データ取得そのものがシミュレーション処理を大きく阻害しないこと。
- 高頻度なメトリクス表示をコアへの直接問い合わせ連打で実現しないこと。
- 一部領域が高負荷でも、どこがボトルネックか識別できること。
- ゲートウェイの複数インスタンスを含めた全体状態を把握できる設計を検討可能にすること。
- 管理操作が通常利用者向けトラフィックと競合する場合でも、影響を制御可能にすること。

## 8. セキュリティ・権限に関する原則

管理ビューは通常ビューより影響の大きい操作を扱うため、以下を重要な設計要件とします。

- 管理者向け機能を一般利用者へ公開しない。
- UI 上で非表示にするだけで権限制御を完結させない。
- 最終的な権限制御はゲートウェイ等の信頼できる境界で実施する。
- 重要操作について監査可能性を確保する。

具体的な認証・認可方式は未確定です。

## 9. 禁止する依存・実装

- シミュレーションコアへの直接接続
- コア内部状態の直接書き換え
- UI 上の表示制御だけを認可手段として扱うこと
- 管理画面の都合でシミュレーションルールを変更すること
- 管理ビューを監視データの唯一の保存先にすること

## 10. 今後決定が必要な事項

- 管理者ロールと権限モデル
- 管理操作一覧
- 監視対象メトリクス
- ログ閲覧機能
- 監査ログ要件
- アラート機能
- 設定変更可能範囲
- 設定変更の反映方式
- 管理ビューの技術スタック
- 障害対応フロー
- 管理操作の承認フローが必要か
- 通常ビューとの共通基盤範囲
