# ゲートウェイ・管理ビュー間プロトコル設計書

## 1. 所有者

本プロトコルの所有者はゲートウェイです。

## 2. 目的

管理ビューが、MachiVerse の各コンポーネントを運用・診断・設定するために必要な情報参照と管理要求を行う契約を定義します。

管理ビューは一般ビューの上位ロールではなく、システム運用者向けの別境界です。

## 3. 設計原則

- 管理ビューはゲートウェイのコード、DLL、内部型を参照しない。
- ゲートウェイは管理ビューのコード、DLL、内部型を参照しない。
- 双方は本プロトコル設計書を契約として実装する。
- 一般ビュー利用者ロールとは別の認証・認可境界とする。
- 一般ビューのアドミニストレーター権限を管理ビュー権限として扱わない。
- 管理ビューから各コンポーネントの内部実装へ直接アクセスしない。
- Config変更や運用コマンドは、対象コンポーネントの管理境界を通じて行う。

## 4. 通信カテゴリ

### 4.1 コンポーネントステータス参照

各コンポーネントの稼働状態、診断状態、負荷、処理状況等を取得します。

具体的なステータス項目は今後定義します。

### 4.2 ログ参照

各コンポーネントの運用・診断ログを参照します。

ログ取得方式、検索条件、保持期間、リアルタイム配信の有無等は今後定義します。

### 4.3 Config参照

各コンポーネントが所有する外部Configのうち、管理ビューへ公開可能な設定項目と現在値を参照します。

### 4.4 Config変更

管理ビューから許可されたConfig変更要求を送信します。

管理ビューがConfigファイルを直接書き換えることは想定せず、対象コンポーネントが変更要求を受理・検証・反映します。

### 4.5 運用コマンド

各コンポーネントへ定義済みの運用コマンドを送信します。

具体的なコマンド一覧、対象、引数、権限、タイムアウト、冪等性は今後定義します。

### 4.6 シミュレーション運用操作

シミュレーションへの運用上の干渉要求を扱います。

コア内部状態を直接変更せず、ゲートウェイからコア・ゲートウェイ間プロトコルへ仲介し、最終的なシミュレーション妥当性判断はコアが行います。

### 4.7 操作結果

Config変更・運用コマンド・シミュレーション操作の成功、拒否、権限不足、妥当性エラー、一時的失敗等を返します。

### 4.8 監査情報

重要な管理操作について、実行主体、対象、時刻、操作内容、結果等を追跡できる情報を扱えるようにします。

## 5. 認可原則

- 管理ビュー利用者を認証する。
- 要求ごとに管理権限を検証する。
- Config変更やコマンド実行をUI表示制御だけで許可しない。
- 一般ビューのロール情報だけを根拠に管理操作を許可しない。
- 対象コンポーネント側でも要求内容の妥当性を検証する。

## 6. コンポーネント到達経路

管理ビューとの外部契約はゲートウェイが所有します。

ただし、シミュレーションコア以外の各コンポーネント自身に対する管理要求について、ゲートウェイがすべて中継するか、コンポーネント別の管理プロトコルを別途設けるかは未確定です。

この点は、コンポーネント間コード依存を作らず、プロトコル契約だけで独立実装できる原則を維持して決定します。

## 7. 禁止事項

- 一般ビューのアドミニストレーターを管理ビュー運用者と同一視すること
- 管理ビューからコンポーネント内部実装へ直接アクセスすること
- 他コンポーネントのConfigファイルを直接編集すること
- UI側だけで管理権限制御を完結させること
- 未定義の内部管理APIを利用すること
- 共有 DTO ライブラリへ依存すること
