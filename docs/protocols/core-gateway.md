# シミュレーションコア・ゲートウェイ間プロトコル設計書

## 1. 所有者

本プロトコルの所有者はシミュレーションコアです。

理由は、シミュレーションコアとゲートウェイのうち、シミュレーションコアの方がシステム中心側に位置し、外部へ公開可能な状態と受理可能な管理操作の意味を定義する責任を持つためです。

## 2. 目的

本プロトコルは、シミュレーションコアと複数のゲートウェイ間で、以下を行うための契約を定義します。

- 外部参照用シミュレーション状態の配信
- ゲートウェイキャッシュ更新に必要な情報の提供
- ゲートウェイが1秒分の遅延バッファを構成するために必要な時間順序情報の提供
- 管理ビュー由来の管理要求の受理
- 管理要求に対する結果の返却
- コアの公開可能な実行状態・診断状態の通知

## 3. 設計原則

- ゲートウェイはコアのコード、DLL、内部型を参照しない。
- コアはゲートウェイのコード、DLL、内部型を参照しない。
- 双方は本プロトコル設計書だけを契約として実装する。
- コア内部の可変状態をプロトコル越しに直接公開しない。
- コアの内部データ構造と通信データ構造を同一視しない。
- 1つのコアに複数ゲートウェイが接続することを前提とする。
- 外部参照負荷をコアへ直接集中させない。
- シミュレーションコアは30Hzを基準として計算する。
- ゲートウェイはコアから受信した状態を約1秒遅延させて外部へ公開し、コア側の一時的な計算間隔の揺らぎを吸収する。

## 4. 時間・順序に関する契約

### 4.1 コア計算頻度

シミュレーションコアの計算頻度は **30Hz** とします。基準上、1ステップは約33.33msに相当します。

この値はコアの計算基準です。ネットワーク到着間隔やゲートウェイからビューへの配信間隔が常に33.33msになることを保証するものではありません。

### 4.2 ゲートウェイ遅延

ゲートウェイは、コアから受信した状態を即時公開せず、**1秒分の遅延バッファ**を持ちます。

目的は、コアの計算時間や通信到着間隔が一時的に揺れた場合でも、その揺らぎをそのまま一般ビュー・管理ビューへ伝播させないことです。

30Hzを基準とすると、1秒は概念上約30計算ステップに相当します。ただし、実装上のバッファ管理を単純に「30メッセージ固定」とするか、時刻・ステップ番号を基準に1秒を判定するかは今後定義します。

### 4.3 時間順序情報

ゲートウェイが1秒遅延と順序制御を正しく行えるよう、状態配信メッセージには、少なくとも状態の時間的位置を一意に判断できる情報が必要です。

候補は以下です。

- シミュレーションステップ番号
- シミュレーション時刻
- 状態生成時刻
- シーケンス番号

どの項目を正式採用するか、型・単位・起点・オーバーフロー時の扱いは今後の詳細プロトコル設計で決定します。

### 4.4 揺らぎ吸収の境界

コアは30Hz計算へ集中し、ビュー向けに一定間隔へ再整形する責任を持ちません。

状態到着の時間的な揺らぎを吸収し、1秒遅延した安定した系列として外部参照側へ渡す責任はゲートウェイにあります。

1秒を超える遅延、長時間の計算停止、欠落ステップ、順序逆転が発生した場合の扱いは別途定義します。

## 5. 主要な通信カテゴリ

### 5.1 状態配信

シミュレーションコアからゲートウェイへ、外部公開可能な状態を提供します。

ゲートウェイは受信した状態を参照用キャッシュおよび1秒分の遅延バッファへ反映します。

具体的な Push / Pull、全量 / 差分 / スナップショット、配信頻度、順序保証は未確定です。

### 5.2 管理要求

管理ビューからゲートウェイへ送られた管理要求のうち、コアへ影響するものをゲートウェイからコアへ伝達します。

コアは要求を受理した後、シミュレーション上の整合性と実行可否を最終判断します。

### 5.3 管理結果

コアは管理要求の処理結果をゲートウェイへ返します。

成功・拒否・競合・一時的失敗・恒久的失敗など、具体的な結果分類は今後定義します。

### 5.4 実行状態・診断状態

管理ビューで必要となるコアの実行状態や診断情報を、ゲートウェイが取得または受信できる契約を定義します。

## 6. バージョニング

プロトコル変更はコア側の実装変更だけで暗黙的に行いません。

変更時は本設計書を先に更新し、ゲートウェイが独立して追従できる状態を作ります。互換性を破る変更を行う場合の版管理方式は今後定義します。

## 7. 並行開発条件

コアとゲートウェイは、同時に別担当者が実装してもソースファイル競合を起こさないことを前提とします。

双方は本設計書に基づくスタブやテスト用通信相手を用いて、相手実装が未完成でも独立して開発・テストできる構造を目指します。

ゲートウェイ側では、30Hz相当の正常系列だけでなく、到着間隔が揺れる系列を模擬して1秒遅延バッファの動作を検証できることが望まれます。
